# Decision log

Every judgement call, numbered so code comments can reference it.

## Design

| # | Decision | Why | Revisit if |
|---|---|---|---|
| D1 | Store event counts and derive scores, rather than storing scores | Re-runnability, point-in-time and scale from one structure | — |
| D2 | Four layers: raw → staging → curated → modelled | Keeps scoring logic in one model | — |
| D18 | Modelled tables have no prefix | They migrate to an application database | — |
| D20 | History table rebuilt in full; only the sitting model is incremental | Small today; a full rebuild keeps validity windows consistent | History grows large |
| D21 | `stg_responses` is an incremental table, not a view | A view re-runs the dedupe across all rows on every read. Per-day partitions are safe because duplicates share a timestamp | — |
| D22 | No `inserted_at` on any output | A run timestamp makes two runs differ by construction | Audit needs load provenance (put it in a side table) |
| D27 | Conversion seed generated by a script with assertions | GOV.UK publishes a web page, not a dataset. A script makes the seed reproducible and every quoted figure checkable | A full table is transcribed |
| D36 | `partition_models` var to turn partitioning off | BigQuery sandboxes force 60-day partition expiry and block DML | A real dataset is available |
| D37 | Test that staged row count matches the source | Sandbox expiry deleted 97% of rows and every other test passed | — |
| D38 | `cur_responses_enriched` is a view | It's only a join. As a table it would be a full 100m-row rebuild every run; as a view the incremental date filter reaches `stg_responses`' partitions | — |
| D39 | The incremental sitting model only writes sittings that started inside the lookback | Otherwise a sitting straddling the cutoff is read partially and overwrites its partition with incomplete counts | — |
| D40 | The current view covers every pupil × subject, with `no_responses` where there's no activity | The brief asks for every pupil in every subject. A missing row looks like a bug | Product prefers to hide unsat subjects |

## Data cleaning

| # | Decision | Why | Revisit if |
|---|---|---|---|
| D3 | Dedupe to one row per (session, question), keeping the lowest `response_id` | Copies share a timestamp, so there's no "latest". `response_id` is a random UUID, so this is deterministic and effectively a random pick, with no bias. Costs ~1.8pp | Atom says which copy is authoritative |
| D4 | Keep responses with no sitting, flagged `sitting_known = FALSE` | 2.2% of evidence, and year group can be recovered | The sittings were deleted deliberately |
| D7 | Exclude Sept 2026 sittings with year groups 11, 14 and 15 | No responses. Looks like QA or a new feature | Atom confirms they're real |
| D8 | Keep zero-second responses | 73% are no-attempts and the rest score at baseline | — |
| D9 | Drop `session_type` | A constant in each table | A second value appears |
| D10 | Count deduplicated responses, not `total_questions` | `total_questions` is wrong for 756 sittings | — |
| D19 | Keep `is_deleted` filters | Empty now, won't be at production volume | — |
| D26 | Impute year group per missing sitting (56), from the pupil's nearest real sitting | Tiny join at sitting grain; never has to scan responses | — |

## Scoring

| # | Decision | Why | Revisit if |
|---|---|---|---|
| D5 | Exclude Wellbeing | A survey: `is_correct` records a chosen option | Quest wants it on another scale |
| D6 | Don't score Screeners, Verbal or Non-Verbal Reasoning | Diagnostic or 11+ content, no KS2 equivalent | Atom wants another scale |
| D35 | Don't score Science | No responses, and KS2 science has no conversion table | Science is assessed |
| D11 | No-attempts count as wrong | A blank scores zero on a real paper | Atom treats skips as not presented |
| D12 | English maps to the reading paper | No topic names to split reading and GPS. The curves are within ~1 point | Topic names are available |
| D13 | Convert percentage to raw mark, not cohort percentile | 164 pupils isn't a national sample, and percentiles make each score depend on everyone else's | National data is available |
| D15 | Apply the latest conversion year, stored on every row | Consistent, and either choice stays reproducible | Atom prefers the tables in force at the time |
| D16 | *Superseded by D28/D29.* Cumulative lifetime scoring | Lagged badly: a Year 6 pupil carries their Year 4 answers | — |
| D17 | Flag low-evidence scores, don't hide them | Hidden rows look like bugs. Consumers choose | Product sets a suppression threshold |
| D24 | Standards flags are NULL, not FALSE, when unscored | FALSE would claim an unscored pupil failed | — |
| D25 | Unmapped subjects appear as `unmapped_subject` | A new subject should show as a gap, not as vanishing pupils | — |
| D28 | The event store is one row per sitting, not per day | A sitting is what a paper scores and a teacher recognises. It's finer than a day, so days can still be derived | — |
| D29 | Headline score pools the current term to date | One sitting has ~±3.5 points of noise. A term cuts that to ~±2.5 and still shows real change | Atom picks another window (one line) |
| D30 | Pool questions, don't average sitting percentages | Weights each sitting by how much it tells us | — |
| D31 | Term-*to-date*, not whole-term | Whole-term is only right at term end, which would break point-in-time. Cost: a visible reset each term | — |
| D32 | Terms by calendar month: Sep–Dec, Jan–Mar, Apr–Aug | No term dates in the data, and Easter moves | Atom supplies real term dates |
| D33 | Publish per-sitting scores too | The trajectory is the product's point | — |

## Point-in-time and history

| # | Decision | Why | Revisit if |
|---|---|---|---|
| D14 | Point-in-time means event time, not knowledge time | Simpler, reproducible, deletions apply retroactively (GDPR-friendly) | Need to reproduce what a dashboard showed on a day |
| D23 | New version only when score, status, reliability or paper changes | Versioning on every new response would just copy the sitting grain | Consumers need exact counts from history |
| D34 | History keeps the end-of-day state | Two sittings on one day would give two rows with the same `valid_from` | — |
